# 中等级问题修复与发布准备

2026-09-23。本轮以群同步重复查询、首次同步监听一致性、日志隐私和重复密码工具为范围；同时验证并准备发布前几轮本地优化。

## 已修复

- 群同步一次读取该账号已有群，以 ID 映射更新；重复 dialog 不再重复插入。保留未返回的历史群、手动禁用状态和空名称时的旧名称。
- 主监听选择由逐群查询改为单次有序查询，仍优先 active 账号，同状态选择最早 Chat ID。disabled 群不改写。
- 修复 autoflush 关闭时刚插入群不参与主监听选择的问题：选择前在同一事务 flush，首次同步即可选出唯一主监听。此字段只服务保留的旧入口，不改变当前 Monitor/DM 的显式群 ID 绑定。
- 旧 worker 日志改为结构化日志，不再输出聊天正文和任意异常字符串，仅记录定位 ID 与异常类型。
- 网页认证与独立 CLI 共用无第三方依赖的密码哈希模块；算法、盐长度、迭代次数与旧密码兼容保持不变。

## 验证

- 临时数据库与模拟 Telegram：98 项测试通过。
- 群同步 2/200 条测试均为 3 次 SELECT（账号、已有群、主监听），不是 3 次总 SQL；写入仍随群数增长。
- 新增首次同步、重复 dialog、禁用群、缺失群、空名称、跨账号主监听排序、日志无正文、CLI 独立运行及密码兼容测试。
- 两套浏览器回归在桌面和手机尺寸通过，页面异常为 0：慢请求、轮询去重、旧响应隔离、文案/权重保存、分页失败恢复和弹窗输入保留。
- JS 语法与 git diff --check 通过。

## 保留与边界

本轮未增加索引、调整 WAL/连接池、清理历史记录、删除旧字段、改变权重/去重/消息状态机。大文件拆分与重复业务状态属于后续重构，未冒充已修复。24–72 小时稳定性、真实 Telegram 完整私信联调仍未完成。部署检查与 GitHub 同步结果另见发布记录，测试通过不等于线上已更新。
