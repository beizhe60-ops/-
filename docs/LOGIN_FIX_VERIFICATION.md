# 登录数据中心切换修复验证

日期：2026-09-22。

## 问题与改动

验证码请求收到 Telegram PhoneMigrateError 时，需要在切换数据中心后继续执行。原统一客户端 request_retries=0，使请求在切换后退出，并由界面把 ValueError 错误显示为两步验证问题。

- 仅 send_login_code / verify_login_code 创建的客户端启用有限请求重试（2 次额外尝试），保留最后的 Telegram 异常类型。
- 这是 Telethon 的请求级重试预算，包含数据中心迁移及其内部可重试的服务器异常；不是仅迁移异常专用循环。FloodWait 阈值仍为 0，非零等待不会自动重试。
- 普通监测、同步和消息发送客户端继续使用 request_retries=0。
- 明确区分需要两步验证、密码错误、数据中心切换、通用请求失败及公开凭据限制。错误响应不包含原始秘密。
- 登录连接失败也执行 disconnect 清理；不改变数据库结构、正式 Session 格式、队列、权重或去重策略。

## 自动化验证

新增 tests/test_login.py，使用真实 Telethon 请求循环和模拟传输，覆盖迁移后继续请求并保存新 DC 临时 Session、重试上限、FloodWait 不重试、普通客户端不重试、连接失败清理和错误脱敏。既有两步验证续登测试通过。

完整测试：50 passed，565 warnings。警告为现有时间 API 和依赖弃用提示；git diff --check 通过。

## 服务器与真实请求验证

仅更新三个相关应用文件，部署前保存旧文件副本。目标服务重启后 active，healthz 返回 ok=true、workers=[]。原转发机器人 PID 与更新前一致。

通过网页请求一次验证码，服务器 send-code 返回 HTTP 200。随后网页显示“两步验证密码不正确”，verify 返回 HTTP 400：验证码请求阶段已恢复，完整账号登录尚未成功。需要用户在网页输入正确的 Telegram 两步验证密码；不代表公开测试凭据可用于长期部署。
