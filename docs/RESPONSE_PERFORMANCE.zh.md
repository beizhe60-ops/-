# 页面响应优化（2026-10-23）

本次只修改前端数据加载与刷新方式，沿用原布局、接口和业务规则；没有数据库迁移、任务启停或发送策略调整。

## 测量

浏览器对比使用同一份虚构数据（300 个群、12 条任务、50 条记录），每个接口固定延迟 500 毫秒。基线为 `053c8df`，计时范围为点击至目标内容/保存成功提示出现，包含浏览器自动化检查开销。以下是单次对比样本，不代表线上平均值或 P95。

| 操作 | 优化前 | 优化后 | 主要变化 |
|---|---:|---:|---|
| 首次打开消息记录 | 1361 ms | 841 ms | 状态与记录并行读取 |
| 消息记录 → AI 分析 | 1350 ms | 824 ms | 只获取本页设置和运行记录 |
| 保存 AI 设置 | 1578 ms | 559 ms | 使用保存响应，运行状态后台更新 |
| AI 分析 → 频道采编 | 1355 ms | 834 ms | 来源和草稿并行读取 |
| 保存采集设置 | 1824 ms | 817 ms | 只更新采集区域，后台刷新帖子 |
| 频道采编 → 账号管理 | 858 ms | 29 ms | 复用 15 秒内的状态快照 |
| 保存账号权重 | 1045 ms | 547 ms | 保存后只更新对应账号卡片 |
| 账号管理 → 监测转发 | 861 ms | 827 ms | 变更后仍校准状态，不复用失效快照 |
| 保存监测绑定 | 1377 ms | 857 ms | 更新对应任务，保留服务器返回的暂停状态 |

线上只读采样从同一台电脑访问，每个接口两次：状态 623–861 ms，消息记录 1035–1039 ms，AI 设置 552–735 ms，AI 运行记录 540–724 ms，采集来源 723–744 ms，草稿 533–551 ms。包含网络传输，不能据此判断服务器处理时间。本轮减少等待链和请求数量，未声称单个后台接口计算更快。

原始、不含凭据或消息正文的测量记录见 [RESPONSE_PERFORMANCE_20261023.json](RESPONSE_PERFORMANCE_20261023.json)。

## 实现边界

- 控制台内切页保留页面外壳，支持地址栏、前进/后退；外部链接、退出、修饰键新开标签保持默认行为。
- 全局状态最多复用 15 秒；专属页面数据每次切页读取。不同接口并行，进行中的相同读取共享请求。
- 修改只在服务器确认成功后应用。写请求不自动重试、不因切页中断；保存后取消旧状态读取，防止旧值覆盖新值。
- AI 保存保留原表单及保存期间继续输入的内容。任务编辑仍保存为暂停，采集设置仍需验证启用；没有增加自动发送动作。
- 快速切页忽略较早的结果；读取失败保留旧页面，保存失败保留输入，筛选失败恢复已应用的条件。
- 群组搜索只在短暂停顿后重绘，减少连续输入造成的重复渲染。
- 新增 `console-loading.js` 负责加载与局部更新；转发、采集、AI 后台引擎和数据库代码未改动。

这些发送测试使用临时数据库和模拟 Telegram/AI 客户端。真实环境仅检查已有运行状态、记录和读取接口，不通过测试额外发送 Telegram 消息或调用 AI。

## 发布与回退

只需发布静态文件，无需重启后台进程。为避免新旧脚本混用，先上传完整静态文件到一个新的版本目录，再原子替换引用该目录的 `console.html`；保留旧资源与原 HTML 作为回退入口。部署过程不触及数据库、会话、密钥、服务开关或其他机器人。用户刷新一次载入新版本后，后续切页复用页面外壳。
