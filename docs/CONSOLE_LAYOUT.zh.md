# 控制台页面结构整理

本轮按账号与记录、AI 与频道采编、工作台与视觉的顺序实施。保留接口、数据模型、发送规则、账号角色与任务启停语义；仅移动入口和重排展示。

## 设计约定

- 延续青绿色识别色：强调 #087f8c、文字 #243849、次要文字 #64798b、底色 #f4f7fa、白色内容区 #ffffff、边界 #dfe7ee。
- 中文使用系统苹方 / 微软雅黑，正文 14px，辅助文字 12px，页面标题 26px。无需下载字体。
- 内容左对齐；账号用紧凑列表，记录用两行摘要加详情，配置使用分区表单。主操作固定放在标题右侧。
- 已保存结果与未保存表单明确区分。页签切换保留同页输入，不重新请求；保留上轮并行加载、请求合并和局部保存。
- 避免把操作台做成介绍页：减少重复说明、大面积留白和层层嵌套卡片。

## 页面结构

```text
工作台                  运行概况 / 待处理提示 / 四个常用功能入口
账号管理                监测账号 / 私信账号
                        登录、连接、发送权限、同步、退出、关联任务入口
群发任务                原有任务列表 / 新建与预览
监测转发                监测任务 / 私信接收
                        按账号筛选、规则启停、接收绑定、文案与权重
频道采编                采编结果 / 采集设置
                        帖子列表与编辑 / 来源、规则、模板及启停
AI 群组分析             分析结果 / 分析设置
                        已保存计划与运行记录、预览推送 / 群组、摘要、接收人、API
消息记录                用户及状态筛选 / 紧凑记录 / 完整详情
不再联系                原有名单与操作
系统设置                原有 Telegram 连接、运行说明、后台密码
```

账号页不再嵌套任务表单或多条任务；原有私信文案与权重入口集中到“监测转发 → 私信接收”。关联入口带入账号筛选，账号类型和绑定数据保持不变。频道设置保存后仍暂停，监测任务编辑保存后仍暂停；AI 操作使用已保存设置。页签本身不启停任务、不发送消息。

## 验证记录

- 原有后台测试：202 项通过，包含转发、采集、AI、账号和队列行为；测试使用临时数据与模拟客户端。
- 浏览器：1440px 桌面和 390px 手机均完成账号、任务、私信接收、记录、AI、频道采编及工作台操作，无横向溢出或脚本错误。
- 页签切换不增加接口请求，保留同页 AI 输入；详情保留完整消息；深链接、返回失败和保存期间返回保持当前页签与账号筛选。
- 原响应优化回归通过：并行初始读取、过期响应隔离、局部保存、失败保留输入、快速切页、筛选失败回滚。
- 固定每个接口 500ms 的本地模拟中，AI 与记录读取仍并行；AI/权重保存约 0.55s。此结果仅用于检查页面额外等待，不代表生产网络耗时。

本轮仅修改页面资源，部署采用带版本的静态文件和原子替换入口，可恢复原入口回退。未更改生产配置、任务开关或数据，验证不额外发送 Telegram 消息。
