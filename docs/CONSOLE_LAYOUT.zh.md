# 控制台页面结构整理

本轮按账号与记录、AI 与频道采编、工作台与视觉的顺序实施。保留接口、数据模型、发送规则、账号角色与任务启停语义；仅移动入口和重排展示。

## 设计约定

- 延续青绿色识别色：强调 #087f8c、文字 #243849、次要文字 #64798b、底色 #f4f7fa、白色内容区 #ffffff、边界 #dfe7ee。
- 中文使用系统苹方 / 微软雅黑，正文 14px，辅助文字 12px，页面标题 26px。无需下载字体。
- 内容左对齐；账号用紧凑列表，记录用两行摘要加详情，配置使用分区表单。主操作固定放在标题右侧。
- 已保存结果与未保存表单明确区分。页签切换保留同页输入，不重新请求；保留上轮并行加载、请求合并和局部保存。
- 避免把操作台做成介绍页：减少重复说明、大面积留白和层层嵌套卡片。

## 页面结构

```text
工作台                  运行概况 / 待处理提示 / 四个常用功能入口
账号管理                监测账号 / 私信账号
                        登录、连接、发送权限、同步、退出、关联任务入口
群发任务                原有任务列表 / 新建与预览
监测转发                监测任务 / 私信接收
                        按账号筛选、规则启停、接收绑定、文案与权重
频道采编                采编结果 / 采集设置
                        帖子列表与编辑 / 来源、规则、模板及启停
AI 群组分析             分析结果 / 分析设置
                        已保存计划与运行记录、预览推送 / 群组、摘要、接收人、API
消息记录                用户及状态筛选 / 紧凑记录 / 完整详情
不再联系                原有名单与操作
系统设置                原有 Telegram 连接、运行说明、后台密码
```

账号页不再嵌套任务表单或多条任务；原有私信文案与权重入口集中到“监测转发 → 私信接收”。关联入口带入账号筛选，账号类型和绑定数据保持不变。频道设置保存后仍暂停，监测任务编辑保存后仍暂停；AI 操作使用已保存设置。页签本身不启停任务、不发送消息。

## 验证记录

- 原有后台测试：202 项通过，包含转发、采集、AI、账号和队列行为；测试使用临时数据与模拟客户端。
- 浏览器：1440px 桌面和 390px 手机均完成账号、任务、私信接收、记录、AI、频道采编及工作台操作，无横向溢出或脚本错误。
- 页签切换不增加接口请求，保留同页 AI 输入；详情保留完整消息；深链接、返回失败和保存期间返回保持当前页签与账号筛选。
- 原响应优化回归通过：并行初始读取、过期响应隔离、局部保存、失败保留输入、快速切页、筛选失败回滚。
- 固定每个接口 500ms 的本地模拟中，AI 与记录读取仍并行；AI/权重保存约 0.55s。此结果仅用于检查页面额外等待，不代表生产网络耗时。

本轮仅修改页面资源，部署采用带版本的静态文件和原子替换入口，可恢复原入口回退。未更改生产配置、任务开关或数据，验证不额外发送 Telegram 消息。


## 后续易用性完善（2026-10-23）

- **任务诊断**：监测任务行新增“诊断”。按需读取现有账号最近 100 条元数据事件，限制为当前任务及来源群；展示接收时间、筛选/跳过原因、当前连接和配置状态，链接到该任务的消息记录。诊断不发消息、不拉取历史内容；重启会清空近期诊断。通过关键词筛选不等于发送成功，交付结果仍以消息记录为准。
- **异常记录**：首页分开显示累计发送失败与结果待核实，并带入筛选。消息记录新增今天（北京时间）、最近 7 天（滚动 168 小时）、全部时间，以及任务筛选，时间按记录创建时间。已删除任务的记录保留可查。筛选和翻页 URL 可分享/返回，失败时保留原结果和已应用查询。
- **输入保护**：AI、监测规则、私信文案、频道设置等编辑页在离开、关闭或刷新前提示未保存修改。折叠、搜索群列表与切换结果/设置页签本身不会误报。保存失败保留输入；AI 保存过程中继续编辑的值仍标记为未保存。凭据及草稿仅在当前页面内存，不写浏览器存储。弹窗保存期间锁定表单避免丢失新输入。
- **局部响应**：群发创建/启停/取消使用接口确认结果更新当前行；取消记录保留筛选输入与页面标题；名单增删只刷新名单区域。失败不提前改变状态，不添加自动重试。
- **长表单**：来源、规则、目标和连接配置分区折叠，提供“展开所有设置”；必填项统一用青色左边框。校验失败会展开对应分区，提交报错保留输入并展开设置便于定位。

服务端仅新增只读记录查询及诊断元数据，不迁移表、不修改发送规则。上线时需要更新少量 Python 模块并受控重启控制台服务；不触碰独立记账机器人、数据文件或凭据。静态资源按版本发布，旧版本与后端文件备份用于回退。


本地验证：后台 209 项测试通过；1440px / 390px 浏览器检查通过，涵盖任务诊断、筛选深链接和失败回退、未保存关闭/返回提醒、保存中继续编辑、群发及名单局部更新。原有页面结构及响应回归通过。固定 500ms 模拟接口下，AI 保存约 0.54s、账号权重保存约 0.55s；这些是本地模拟数据，不代表服务器网络耗时。未向真实 Telegram 用户或群组发送测试消息。
