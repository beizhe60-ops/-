# PHASE 1 低风险优化记录

2026-09-22。本轮仅本地优化；未部署、未连接 Telegram 发送消息。

## 改动

- console_api：单次状态响应内复用应用配置和账号权重，减少重复 SQL；不存在跨请求缓存。缺省权重仍为 1，凭据仍不返回，配置修改或删除在下一次请求生效。
- 集中三个文案字段共用的 3500 字符限制，以及消息记录的 50 条分页常量，原数值与验证语义不变。
- 为账号序列化参数和返回值补基础类型注解。
- 删除 main.dashboard 在无条件 redirect 后永远不可执行的旧统计及模板返回代码；保留原路由、认证、依赖和跳转结果。
- 新增测试覆盖 SQL 读取预算、默认值、配置更新和删除、凭据不回显及根页面跳转。

没有修改队列、锁、权重算法、去重、Schema、Telegram 登录/Session、关键词和群绑定逻辑；没有修改前端、依赖或生产配置。保留任务开始时已有的其他未提交改动。

## 同规模复测

与 PHASE 0 使用同一个临时数据库测量脚本；每接口预热 1 次后串行请求 10 次，数据全部虚构，包含认证查询。账号、任务、群及历史记录数量保持对应一致。

|账号数|状态接口 SQL 次数 Before → After|平均响应毫秒 Before → After|
|---:|---:|---:|
|2|17 → 15|3.645 → 3.397|
|20|89 → 69|26.404 → 24.539|
|100|409 → 309|125.916 → 118.271|

查询量的下降是确定性结果；本地短时延迟受调度与缓存影响，不代表线上延迟承诺。账号级 N+1 仍存在，本轮没有提前实施批量加载。原始证据见 performance-baseline/api.json 与 phase1-api.json。
